emoji 短代码大全：Slack / GitHub / Discord 短代码对照表与使用方法

Emoji 大全 · 2026-09-13

在 Slack、GitHub、Discord、飞书文档等平台，直接输入 :smile: 就能插入表情，这就是 emoji 短代码（shortcode）。它解决了一个核心痛点：表情在不同系统上显示不一致，但短代码是纯文本，人人都能输入。本文讲清三大平台的写法差异、常用短代码速查和踩坑点。

什么是 emoji 短代码

短代码是「冒号 + 英文别名 + 冒号」的纯文本写法，例如 :heart: 代表 ❤️、:thumbsup: 代表 👍。平台在渲染时把它替换成对应 emoji。它的好处是：

  • 键盘党友好：不用打开表情面板盲找
  • 跨平台一致：Windows、Mac、手机显示效果不同，但短代码相同
  • 可搜索、可记忆：:tada: 比翻面板快得多

三大平台短代码对照表

主流平台都基于 GitHub 维护的 CLDR（Common Locale Data Repository）短代码标准，差异主要在「别名」和「彩色变体写法」上。

平台差异速记

  • GitHub / 评论区 Markdown：只在 Issue、PR、README 评论里渲染短代码，普通网页不渲染。
  • Slack：支持最完整，还允许团队自定义表情，:+1: 与 :thumbsup: 等价。
  • Discord：默认只渲染标准短代码，服务器自定义表情用 <:名字:ID> 格式。

常见踩坑

1. 短代码不渲染，原样显示

检查三点：所在输入框是否支持（纯代码编辑器不渲染）、冒号是英文半角 :、拼写正确（:sweat_smile: 下划线不能省）。

2. 肤色与性别变体写法

带肤色的 emoji 要追加后缀，如 :+1::skin-tone-3:；性别变体如 :man: / :woman:。

3. 短代码 ≠ Unicode 字符

短代码是平台层语法，复制出来发给不支持的 App（如记事本）就只是纯文本。需要「真 emoji 字符」时应直接复制图形字符。
